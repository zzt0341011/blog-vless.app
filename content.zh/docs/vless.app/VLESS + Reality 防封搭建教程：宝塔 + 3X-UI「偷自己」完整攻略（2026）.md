# 节点总被封 TCP？Reality 协议正确搭法全攻略：宝塔 + 3X-UI「偷自己」深度解析

近期不少用户遇到了节点突然失联的怪现象：服务器能 ping 通、UDP 也正常，唯独所有新的 TCP 连接（甚至连 SSH）全部中断。很多人因此怀疑是 Reality 协议失效了，但事实并非如此——问题往往出在“图省事”的搭建方式上，没有把 Reality 的伪装特性发挥到位。

本教程前半部分手把手教你如何用 **宝塔面板 + 3X-UI** 搭建一套高伪装度的「偷自己」Reality 节点（附带 AI 住宅 IP 分流方案），后半部分为你彻底拆解每一步背后的技术原理。

### 第 2 步：SSH 连接服务器

系统重装完成后，使用系统自带工具连接服务器（Mac 打开「终端」，Windows 打开 PowerShell）。输入以下命令并回车，确认后输入密码登录（密码输入时不可见）。  
也可以使用图形化 SSH 客户端 [FinalShell](https://www.hostbuf.com/t/988.html)。

```bash
ssh root@你的服务器IP
```

### 第 3 步：安装防火墙与宝塔面板

1. **安装 UFW 防火墙**：在终端输入 `apt install ufw` 并确认安装。
2. **安装管理面板**：可使用宝塔面板；如果不方便绑定国内手机号，也可以使用 aaPanel、1Panel 等同类面板替代。

```bash
URL=https://www.aapanel.com/script/install_panel_en.sh && if [ -f /usr/bin/curl ];then curl -ksSO $URL ;else wget --no-check-certificate -O install_panel_en.sh $URL;fi;bash install_panel_en.sh dbbd1c69
```

### 第 4 步：安装 3X-UI 并临时放行面板

1. 登录宝塔面板后，直接打开宝塔自带的「终端」，运行 3X-UI 安装脚本完成安装。
2. 由于此前安装了防火墙，刚装好的 3X-UI 面板默认无法打开。此时进入宝塔的 **「安全」** 页面，暂时关闭防火墙（或放行对应端口），随后即可使用账号密码登录 3X-UI 面板。

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

### 第 5 步：安装建站环境（Nginx、PHP、MySQL）

回到宝塔的 **「软件商店」**，极速安装 **Nginx**。为了搭建一个真实的伪装网站，建议同时安装 **PHP** 和 **MySQL**（安全性与复杂度成正比）。

![vless-3xui-feng1004.png](https://vless.app/img/vless-3xui-feng1004.png)

### 第 6 步：域名解析与建站（关键防坑点）

1. **配置 DNS 解析**：建议使用独立的顶级域名（不推荐免费二级域名），添加一条 A 记录指向你的服务器 IP，主机名可设为类似 `api` 等常见业务名称。
2. **关闭代理（灰云朵）**：如果使用 Cloudflare 解析，**务必关闭代理状态（小云朵变为灰色）**，仅做 DNS 解析。
3. **建站并申请证书**：在宝塔「网站」中添加刚才解析好的域名，申请免费的 SSL 证书，并开启 **「强制 HTTPS」**。
4. **替换网页内容**：将网站根目录的默认页面替换为真实的网站内容或自定义单页。

![vless-3xui-feng1005.png](https://vless.app/img/vless-3xui-feng1005.png)

### 第 7 步：修改 Nginx 配置，让出 443 端口

这一步是「偷自己」的核心。进入宝塔「网站」→ 点击对应站点的 **「设置」** → **「配置文件」**，修改以下两处并保存：

1. **更改监听端口**：将原本监听的 `443` 端口改为 `8443`（也可进一步限定仅监听本地回环地址 `127.0.0.1:8443`），把标准的 443 端口让出来。
2. **修改强制跳转规则**：找到配置中「端口不等于 443 则跳转」的那一行（包含 `!= 443`），**删掉感叹号 `!`，并将 `443` 改为 `80`**（即仅当端口为 80 时才跳转 HTTPS）。

> 保存后此时访问网站会暂时打不开，这是正常现象，因为 443 端口已经让出但尚未由 3X-UI 接管。

![vless-3xui-feng1006.png](https://vless.app/img/vless-3xui-feng1006.png)

### 第 8 步：在 3X-UI 创建 Reality 入站节点

回到 3X-UI 面板，点击 **「入站」** → **「添加入站」**，按以下参数配置：

- **端口**：必须设为 `443`
- **安全**：选择 `Reality`
- **目标（Dest）**：填写 `127.0.0.1:8443`（必须与上一步 Nginx 配置文件中的端口一致）
- **扫描与密钥**：点击扫描（此时会出现证书报错，属正常现象，直接点确定），随后获取新的密钥对，点击创建并添加客户端

创建完成后，重新刷新你的伪装网站，此时网页应已恢复正常访问，节点也可正常连通。

![vless-3xui-feng1007.png](https://vless.app/img/vless-3xui-feng1007.png)

### 第 9 步：重开防火墙，收紧暴露端口

回到宝塔 **「安全」** 页面，重新开启防火墙，并批量删除多余的开放端口（如 20、21、888、FTP 等），仅保留必要端口（如 22、80、443 及宝塔面板端口）。

- 3X-UI 面板端口平时不对外放行，需要调整配置时再临时添加放行规则，用完即删。

![vless-3xui-feng1008.png](https://vless.app/img/vless-3xui-feng1008.png)

## 二、进阶配置：为 AI 服务配置住宅 IP 分流

如果你的节点需要用于访问对机房 IP 风控较严的 AI 服务，可以通过 3X-UI 的出站分流功能挂载静态住宅 IP：

1. **购买静态住宅 IP**：地区除了美国外，也可考虑新加坡或日本（处于 UTC+8 时区，与国内作息一致，使用特征更自然；购买前需确认该地区在目标 AI 服务支持列表中）。
2. **添加 SOCKS5 出站**：获取住宅 IP 的 SOCKS5 代理信息后，在 3X-UI 的 **「出站」** 中新建一个 `socks` 协议出站（标签可自定义为 `us-home`），填入地址、端口、用户名和密码，测试真实延迟通过后保存。
3. **设置 AI 专属路由规则**：进入 **「路由」** → **「路由规则」** 新建规则，在域名栏点击浏览分类并搜索选中 `AI`，将出站标签指向刚才创建的住宅 IP 出站并保存。这样就实现了「仅 AI 流量走住宅 IP，其余流量直连服务器」，兼顾速度与流量成本。

## 三、原理解析：为什么要这么「折腾」？

### 1. 为什么以前「偷微软、苹果」容易被封？

Reality 的工作机制是在 TLS 握手的第一个数据包里藏入暗号：暗号对得上就转发代理流量；对不上（如遇到主动探测），服务器就把整条连接原封不动地转发给目标网站。

过去大家为了省事，直接把目标填成微软、苹果等大站，但这存在三个隐患：

- **身份与地址不符**：服务器是搬瓦工洛杉矶的 IP，却自称是微软，查一下 DNS 就能发现该 IP 根本不属于微软。
- **握手延迟异常**：每次探测，服务器都要跨网去连远端的微软再把结果传回来，延迟表现不自然。
- **沦为公开跳板**：如果借用的目标网站套了 Cloudflare，服务器还可能变成公开跳板。

而采用 **「偷自己」** 方案后，域名、DNS 解析、SSL 证书以及真实运行的网站全部都在同一台服务器上，无论外部如何探测，信息完全严丝合缝，且目标就在本机（`127.0.0.1`），转发延迟极低。

![vless-3xui-feng10091.png](https://vless.app/img/vless-3xui-feng10091.png)

### 2. 既然都有真实证书了，为什么不用传统 TLS 回落？

核心原因有两点：

- **消除服务端 TLS 指纹**：传统 TLS 方案中，负责与探测者握手的始终是 Xray 程序本身，解密后才回落给 Nginx；而 Reality 遇到陌生连接根本不解密，直接原样转交给 Nginx，探测者全程在和真正的 Nginx 网站握手，彻底消除了服务端 TLS 指纹。
- **对建站环境改动小**：传统 TLS 回落给 Nginx 的是明文，需要额外开明文端口且容易与宝塔的强制 HTTPS 冲突；而在 Reality 方案下，Nginx 照常运行 HTTPS，只需挪到本机 8443 端口，不影响证书续签和站点维护。

![vless-3xui-feng10092.png](https://vless.app/img/vless-3xui-feng10092.png)

### 3. 几个「反直觉」操作背后的原因

- **为什么要装 PHP/MySQL 建真实网站？** 如果探测者打开你的域名只看到空白页或默认页，几乎等于没有伪装；一个有正常内容的网站才最不显眼。
- **为什么必须关掉 Cloudflare 小云朵？** 一方面 Reality 本身过不了 CDN；另一方面开启代理后，域名解析会变成 Cloudflare 的 IP，与客户端直连的服务器真实 IP 再次对不上。
- **为什么 Reality 必须占 443，Nginx 要挪到 `127.0.0.1:8443`？** 正常 HTTPS 网站都在 443 端口，非 443 端口会增加被封概率；将 Nginx 限制在本地回环，可防止外网扫描器在 8443 端口扫出第二个一模一样的网站。
- **为什么要删掉 Nginx 配置文件里的感叹号？** 宝塔默认规则是「端口不等于 443 就强制跳转 HTTPS」。当 Nginx 改为 8443 后，如果不修改该规则，会造成无限跳转死循环；改为「端口等于 80 才跳转」即可解决。
- **为什么扫描时报证书错误却不用管？** 因为扫描时是用 `127.0.0.1` 去校验你域名的证书，主机名自然对不上；只要确认支持 TLS 1.3 且 ALPN 为 h2，就符合 Reality 要求。
- **为什么最后一定要重开防火墙并关掉多余端口？** 对外暴露的端口和管理面板越多，特征就越像专门的代理节点机，同时也会增加被暴力破解的风险。
